# Spec品質保証ルール

## 基本方針

ローカルで品質を作り込み、CI/CDで公開品質を証明する。検証はhookで自動実行される。

## 検証スクリプト

`project-config.yml` の `quality.spec_validation` に定義:

1. `validate_specs.py`（構造検証）: Front Matter必須フィールド、日付フォーマット、必須セクション
2. `check_spec_consistency.py`（一貫性検証）: 3ファイル間のfeature名一致、受入基準の参照整合性

## 警告の扱い

修正必須（トレーサビリティ）:
- タスクが受入基準をカバーしていない
- プロパティが受入基準を参照していない

許容可能（推奨事項）:
- 受入基準が3個未満（小さな機能なら2個でもOK）
- 正確性プロパティが3個未満
- WHEN-THEN形式がない
- タスクの50%未満に要件記載がない

## 検証タイミング

1. Spec完成時（3ファイル揃った後）→ hookで自動実行
2. 実装開始直前 → hookで自動実行
3. Spec修正後 → 再検証を推奨（必須ではない）

## 検証結果の対応

- エラーあり → 実装を開始しない、修正を優先
- トレーサビリティ警告あり → 実装を開始しない、修正を提案
- 推奨事項の警告のみ → ユーザーに確認して判断
